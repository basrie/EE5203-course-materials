Midterm Study Sheet

EE5203 Microprocessors — what the exam covers (L01–L07), how the questions look, and practice with answers

Author

Basri Erdogan — 2026-2027 Fall

Rule: try every practice item on paper before you open the answers at the end. The exam is written by hand, closed book, 80 minutes. Practice the same way: no compiler, no debugger, a pen and this sheet.

How the exam works

Section Questions Points What you do
A — Trace the execution 4 × 6p 24 Read a short C program. Write exactly what it prints, or the final register / variable values.
B — Multiple choice 5 × 4p 20 One correct answer per question. Concepts from L01–L07.
C — Fill in the blank 2 × 5p 10 A working program with five blanks. One point per blank.
D — Short code 4 questions 46 Write a small function or a loop body. Minimal C; comments welcome.

Every question gives you the facts it needs: the pin, the bit positions, the timer clock, the HAL names. The first page of the exam is a reference box with the HAL and CMSIS names you may use. You do not memorise register addresses, bit encodings or function names. You do need to be fluent in the patterns below.

Board facts you may assume: Nucleo-F401RE, LD2 on PA5, B1 on PC13 (external pull-up, pressed = pin low), timer clock 16 MHz.

L01 — Toolchain and evidence

Stage Tool Its message when it fails Typical cause
Compile compiler error: ... undeclared, expected ';' typo, missing declaration, syntax
Link linker undefined reference to 'f' f is declared but defined nowhere in the build (the .c file is not in the build, or the body was never written)
Flash ST-LINK connection / target errors cable, board, wrong project
Run the board nothing — you must observe logic or configuration error
  • A clean build proves the source is valid C, not that the board does what you want.
  • A successful flash proves the firmware reached the board, not that it behaves correctly.
  • Evidence is an observation: the LED, a variable in the debugger, a register in the SFR view.
  • HAL_Delay(100) blinks faster than HAL_Delay(500) because the loop waits less between toggles.

L02 — Values, loops, decisions, arrays

Rule Example
Integer division discards the fraction 17 / 5 is 3; 17 % 5 is 2
= stores, == compares if (x = 1) is a bug: it stores 1 and is always true
> is strict, >= is not 3000 > 3000 is false; 3000 >= 3000 is true
for (int i = 0; i < N; i++) runs the body N times i is 0 … N-1 inside; N is never used as an index
Valid indices of uint16_t a[N] 0 … N-1; a[N] is outside the array
Accumulators start at a known value sum = 0, count = 0, maximum = a[0]
Clamp before you add if (a[i] > 4095) a[i] = 4095; then sum += a[i];

How to trace a loop on paper: make a table with one row per repetition and one column per variable. Write the value of every variable after the body. Stop when the condition is false. Then compute what is printed.

printf in the trace questions. We hardly used printf in the labs (the board has no screen); in the exam it is only the way a question asks “what are the values now?”. printf("format", a, b, …) prints the format text and replaces each %… with the next value, in order. Everything else in the format text is printed as it is.

Specifier Prints Example
%d a signed integer (int) printf("%d", -5) → -5
%u an unsigned integer (uint32_t, uint16_t, uint8_t) printf("%u", 14995U) → 14995
%02X the value in hexadecimal, capital letters, at least 2 digits, zero-padded 0x4C → 4C, 0xC → 0C
%08X the same with 8 digits 0x40C → 0000040C
\n ends the line
  • printf("%d %d\n", 12, 13) prints 12 13: one space between the numbers because there is one space in the format text. "%d,%d" would print 12,13.
  • An expression is evaluated first: printf("%d", sum / 6) prints the result of the integer division, not the expression.
  • On the answer line write exactly what is printed: the digits and spaces, no quotes, no units, no variable names.

L03 — Functions, arrays as parameters, strings

  • A declaration (in the .h) has three parts: return type, name, parameters. The definition (in the .c) adds the body. The call uses the return value.
  • Parameters are copies. Changing a parameter never changes the caller’s variable. To send a result back, return it, and the caller must store it: x = f(x);.
  • An array parameter uint16_t values[] is not a copy and does not know its own length: the caller passes count. Loop with i < count.
  • Sum many uint16_t values into a uint32_t: 17 × 4095 already exceeds 65535.
  • #define SAMPLE_COUNT 8 is text replacement; it is not a variable.
  • A C string ends with '\0'. "HIGH" needs 5 bytes. {'O','K'} is not a string. Compare strings with strcmp(a, b) == 0, never with ==.

L04 — Pointers, structures, bits, registers

int x = 5;      int *p = &x;      /* p holds the ADDRESS of x            */
*p = 9;                            /* write THROUGH p: x is now 9         */
s.member                           /* member of a structure value         */
p->member   /* same as (*p).member: member through a pointer              */

Mask recipes (n = bit number, k = first bit of a 2-bit field = 2 × pin):

r |=  (1U << n);                       /* set bit n, other bits unchanged      */
r &= ~(1U << n);                       /* clear bit n: ~ inverts the mask      */
r ^=  (1U << n);                       /* toggle bit n                         */
if (r & (1U << n)) { /* bit n is 1 */ } /* test bit n: non-zero means set      */
r &= ~(3U << k);  r |= (pattern << k); /* replace a 2-bit field: CLEAR FIRST   */

Hex ↔︎ binary: one hex digit = four bits. 0x3 = 0011, 0xC = 1100, 0xF = 1111. 1U << n is the hex number with a single 1 at bit n: 1U << 4 = 0x10, 1U << 12 = 0x1000, 3U << 12 = 0x3000.

GPIO registers (CMSIS names):

Register Rule
RCC->AHB1ENR bit 0 = GPIOA clock, bit 1 = GPIOB, bit 2 = GPIOC. Enable the clock first; an unclocked port ignores writes.
GPIOx->MODER pin n owns bits 2n+1:2n. 00 input, 01 output, 10 alternate, 11 analog. Read-modify-write.
GPIOx->BSRR bit n (0–15) sets pin n high; bit n+16 sets it low. Plain = is correct: each write is a command.
GPIOx->IDR input level of all 16 pins; (IDR >> n) & 1U reads pin n.
GPIOx->ODR current output levels; ^= toggles a pin. 
/* worked example: an external LED on PB7 */
RCC->AHB1ENR |= (1U << 1);      /* GPIOB clock (bit 1)                 */
GPIOB->MODER &= ~(3U << 14);    /* clear PB7 field (bits 15:14 = 2·7)  */
GPIOB->MODER |=  (1U << 14);    /* 01 = output                         */
GPIOB->BSRR   =  (1U << 7);     /* PB7 high                            */
GPIOB->BSRR   =  (1U << 23);    /* PB7 low (7 + 16)                    */
GPIOB->ODR   ^=  (1U << 7);     /* toggle PB7                          */

Work the same five lines out for LD2 on PA5 yourself: which clock bit, which MODER bits, which BSRR bits? GPIOB is a pointer to a GPIO_TypeDef structure, so GPIOB->MODER is a member reached through a pointer.

L05 — HAL GPIO

GPIO_InitTypeDef cfg = {0};
cfg.Pin  = GPIO_PIN_5;              /* a mask: 1U << 5                     */
cfg.Mode = GPIO_MODE_OUTPUT_PP;     /* MODER field 01, OTYPER bit 0        */
cfg.Pull = GPIO_NOPULL;             /* PUPDR field 00                      */
HAL_GPIO_Init(GPIOA, &cfg);         /* &cfg: the function reads your struct */
HAL name Register effect for pin n
GPIO_MODE_INPUT MODER field 00
GPIO_MODE_OUTPUT_PP MODER field 01, OTYPER bit n 0
GPIO_MODE_IT_FALLING MODER 00 + EXTI falling edge + line unmasked
GPIO_NOPULL / GPIO_PULLUP / GPIO_PULLDOWN PUPDR field 00 / 01 / 10
  • Run-time: HAL_GPIO_WritePin(port, pin, GPIO_PIN_SET/RESET), HAL_GPIO_TogglePin(port, pin), HAL_GPIO_ReadPin(port, pin) returns GPIO_PIN_SET (high) or GPIO_PIN_RESET (low).
  • A floating input reads noise. A pull-up makes the released level high; a pull-down makes it low. If the board already has an external resistor, use GPIO_NOPULL.
  • Read the wiring, not the word “pressed”: a button that connects the pin to GND gives a low level when pressed; a button that connects the pin to 3.3 V gives a high level. Work out what HAL_GPIO_ReadPin returns from that.
  • A button pressed for a long time is one press: detect the edge (previous level high, current level low), not the level.

L06 — Interrupts

press -> PC13 falls -> EXTI13 edge detect -> EXTI->PR bit 13 = 1 (pending)
      -> EXTI->IMR bit 13 must be 1 -> EXTI15_10_IRQn -> NVIC enable must be 1
      -> CPU saves its place -> vector table entry -> EXTI15_10_IRQHandler()   (processor enters)
      -> HAL_GPIO_EXTI_IRQHandler()  (clears PR)  -> HAL_GPIO_EXTI_Callback(pin)  (you write this)
  • Two enable switches: EXTI->IMR (written by HAL_GPIO_Init) and the NVIC (HAL_NVIC_EnableIRQ). With the NVIC switch open, EXTI still sets the pending bit, but the handler never runs.
  • EXTI->PR is write-1-to-clear; the HAL helper clears it. Your button_event variable is a different flag: main() clears it.
  • Callback rules: check the pin, record the event, return. No HAL_Delay(), no loops, no LED code.
  • A variable shared with an interrupt is volatile: otherwise the compiler may keep a stale copy in a register and main() never sees the change.
  • Debounce: accept an edge only if now - last >= GUARD (unsigned subtraction, wrap-safe). Update last only on an accepted edge. >= accepts an edge exactly GUARD ms after the last one.

L07 — Timers

\[f_{\text{counter}} = \frac{f_{\text{timer clock}}}{\text{PSC}+1}\qquad T_{\text{update}} = \frac{\text{ARR}+1}{f_{\text{counter}}}\qquad f_{\text{update}} = \frac{f_{\text{timer clock}}}{(\text{PSC}+1)(\text{ARR}+1)}\]

  • Both +1s. PSC = 0 divides by 1. ARR = 99 means 100 counts (0 … 99).
  • Many PSC/ARR pairs give the same period; a smaller PSC gives finer resolution.
  • HAL_TIM_Base_Start(&htim) runs the counter only. HAL_TIM_Base_Start_IT(&htim) also enables the update interrupt (UIE). Without _IT the callback never runs.
  • Polling: test TIMx->SR & TIM_SR_UIF, then clear it. Forget the clear and the loop fires continuously.
  • Interrupt: the HAL clears UIF and calls HAL_TIM_PeriodElapsedCallback(htim). One callback serves all timers: before acting, compare the handle’s timer-peripheral member with the timer you expect (the member name is on the exam’s reference page).
  • Tick pattern: the callback only adds one to the millisecond counter. main() schedules with if ((g_ms - t_task) >= INTERVAL) { t_task = g_ms; /* work */ }. No HAL_Delay() anywhere in that loop.

Part D — Write the code

Answers

Part A

A1. 12795 3 2559. The 4300 is clamped to 4095 before it is added: 1200 + 4095 + 3000 + 1500 + 3000 = 12795. >= 3000 counts 4095, 3000 and 3000 (three). 12795 / 5 = 2559 exactly.

A2. 7 then 14. double_it changes its own copy n; v in main() is untouched. twice returns 14 and the caller stores it with v = twice(v).

A3. 15 12 15 12. *p += 5 writes through the pointer, so m is 15; n is 12; pr->value = n sets r.value; r.id = m.

A4. A2. 0xF0 = 1111 0000 → set bit 1 → 1111 0010 (0xF2) → clear bit 4 → 1110 0010 (0xE2) → clear bits 7:6 → 0010 0010 (0x22) → write 10 at bits 7:6 → 1010 0010 (0xA2). Bits 7:6 belong to pin 3 (2 × 3 = 6): PB3, alternate function (10).

A5. Accepted: 300 (300 − 0 ≥ 50), 360 (360 − 300 = 60), 420 (60), 470 (470 − 420 = 50, and >= accepts exactly 50). Rejected: 310 (10) and 345 (45). last ends at 470. Four events.

A6. 0 1 4 9 16 — the body runs 5 times because the condition is <=.

Part B

B1. The compiler. A declaration of mean is missing before its first use (a variable declaration or a function prototype / header include).

B2. The linker. The header gave the compiler a declaration, so every call compiled. No object file in the build contains the definition: the .c file is not in the build list or the body was never written.

B3. A random, unstable value: the input is floating. Nothing defines the level.

B4. GPIO_PULLDOWN, so the released pin reads low. A press connects it to 3.3 V and reads GPIO_PIN_SET (active-high).

B5. Pin 7 owns bits 15:14. MODER[15:14] = 01 (output), PUPDR[15:14] = 10 (pull-down). Also OTYPER bit 7 = 0 (push-pull).

B6. The processor enters EXTI15_10_IRQHandler(), the function named in the vector table. The HAL then calls your callback, HAL_GPIO_EXTI_Callback(), with GPIO_PIN_13 as its argument.

B7. It reads 1: the edge is pending and not yet serviced. The HAL helper HAL_GPIO_EXTI_IRQHandler() clears it by writing 1 to the bit, before it calls your callback.

B8. Counter frequency 16 MHz / (7 + 1) = 2 MHz. Update period (19999 + 1) / 2 MHz = 20000 × 0.5 µs = 10 ms (100 Hz).

B9. TIM2->DIER bit 0 (UIE) is 0: the update event never raises an interrupt. Call HAL_TIM_Base_Start_IT(&htim2) instead (and keep the NVIC line enabled).

B10. The clear: TIM2->SR &= ~TIM_SR_UIF; (or __HAL_TIM_CLEAR_FLAG(&htim2, TIM_FLAG_UPDATE)). The flag stays set, so every pass of the loop “sees” an update.

B11. The interrupt changes g_ms between two instructions of main(). Without volatile the compiler may keep a copy in a register and reuse the stale value; volatile forces a fresh read from memory every time.

B12. Unsigned subtraction wraps the same way the counter does: for example 3 - 0xFFFFFFFE gives 5, the true elapsed time. g_ms >= t + 500 would not survive the wrap.

C2. 0, count, >, ++, n.

C3. volatile, GPIO_PIN_13, ++, 10, press_count (or shown).

C4. 799 (16 MHz / 800 = 20 kHz), 499 (20 kHz / 500 = 40 Hz = 25 ms), HAL_TIM_Base_Start_IT, TIM3, GPIO_PIN_5.

Part D

D1.

uint16_t minimum_sample(uint16_t values[], int count)
{

        return 0U;

int text_length(char text[])

D3.

void gpio_set_pull(GPIO_TypeDef *port, uint32_t pin, uint32_t pull)
{
    port->PUPDR &= ~(3U << (2U * pin));           /* clear the field */
    port->PUPDR |=  ((pull & 3U) << (2U * pin));  /* write the pattern */
}

uint32_t gpio_read(GPIO_TypeDef *port, uint32_t pin)
{
    return (port->IDR >> pin) & 1U;
}

D5.

volatile uint8_t button_event = 0;
uint8_t  presses = 0;

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_13) {
        button_event = 1;                 /* record only */
    }
}

while (1) {
    if (button_event == 1) {
        button_event = 0;                 /* consume first */
        presses++;
        if (presses == 3) {
            presses = 0;
            HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);
        }
    }
}

The L06 lab’s 50 ms guard (uint32_t now = HAL_GetTick(); and (now - last_press_ms) >= 50U in the callback, with last_press_ms = now; on an accepted edge) is a good extra, but the exam does not ask for it in the code question; the trace question (A5) covers it.

D6.

uint32_t t_log = 0;                   /* declared next to t_led */

    /* at the "your code" comment, a sibling of the LED block */
    if ((g_ms - t_log) >= 1000U) {
        t_log = g_ms;
        log_values();
    }

t_led += 250U keeps every deadline on the original 250 ms grid, so a late pass delays one toggle but not the following ones; t_led = g_ms re-anchors to the late moment and the lateness accumulates. g_ms is written by the TIM2 interrupt outside the flow of main(); volatile forces every read to go to memory, so the loop sees each new value instead of a copy the compiler kept in a register.

D7.

while (1) {
    if (TIM2->SR & TIM_SR_UIF) {        /* 1. test the flag  */
        TIM2->SR &= ~TIM_SR_UIF;        /* 2. clear it       */
        HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);
    }
}

The counter must be running (HAL_TIM_Base_Start(&htim2) or TIM2->CR1 |= 1U).
