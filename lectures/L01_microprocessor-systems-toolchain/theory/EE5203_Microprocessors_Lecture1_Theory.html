The smallest control loop

SourceCompileLinkFlashRunDebug 
while (1)
{
    HAL_GPIO_TogglePin(LD2_GPIO_Port, LD2_Pin);
    HAL_Delay(500);
}

Toggle a physical output · wait about 500 ms · repeat forever. This is the statement we follow for the rest of the lecture — and every later lecture replaces one part of this loop.

Reading main()

SourceCompileLinkFlashRunDebug 
int main(void)
{
    /* initialise once: clocks, pins */

    while (1)
    {
        HAL_GPIO_TogglePin(LD2_GPIO_Port, LD2_Pin);
        HAL_Delay(500);
    }
}

01 After reset, the startup code calls main(). Execution enters here.

02 The braces group the statements that belong to main().

03 Statements run top to bottom — and the loop never lets execution reach the end.

Declaring a variable

SourceCompileLinkFlashRunDebug 
int toggle_count = 0;

01 int — the variable stores a whole number.

02 toggle_count — the name later statements use.

03 0 — the first stored value.

04 ; — ends the declaration.

In the lab you add exactly this line, then watch the value change in the debugger.

The forever loop

SourceCompileLinkFlashRunDebug 
int main(void)
{
    int toggle_count = 0;

    while (1)
    {
        HAL_GPIO_TogglePin(LD2_GPIO_Port, LD2_Pin);
        toggle_count = toggle_count + 1;
        HAL_Delay(500);
    }
}

while (1) means repeat forever. Firmware initialises the hardware once, then stays in its main loop.

Where your code lives

This is the layout CubeMX generates. Your statements live inside a USER CODE region; everything outside can be regenerated from the .ioc configuration.
