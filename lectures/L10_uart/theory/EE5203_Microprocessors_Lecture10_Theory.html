Serial communication: one wire instead of eight

A byte has 8 bits. Parallel communication sends them on 8 wires at once. Serial communication sends them on one wire, one after another.

UART means universal asynchronous receiver-transmitter. Asynchronous: no clock wire. The receiver uses its own clock at the agreed speed.

A UART frame: start bit, 8 data bits, stop bit

The line is high when nothing is sent. Every byte travels as one frame. Example: the character A, 0x41.

Baud rate: bits per second. One bit lasts 1 ÷ baud rate: 8.68 µs at 115200 baud. 8N1: 8 data bits, no parity, 1 stop bit. One byte is 10 bits on the wire.

Deep dive: RM0368 Rev 6, §19.3.1 USART character description — p. 510.

Practice: UART time for one line

One byte is one 8N1 frame: 10 bits. The line 12300,1241,1000\r\n has 17 characters.

1

\(17 \times 10\)

2

\(\dfrac{170}{115\,200}\) s

3

The board sends 10 lines per second. What part of each second does the UART use?

\(\dfrac{10 \times 1.48\ \text{ms}}{1000\ \text{ms}}\)

1.5 % of the time

4

\(\dfrac{170}{9600}\) s

17.7 ms

Check: 115200 is 12 × 9600, and 17.7 ms ÷ 12 = 1.48 ms.

USART2 reaches the PC through the ST-LINK

On the Nucleo board, PA2 and PA3 are already connected to the ST-LINK. You need no extra wires.

CubeMX: USART2 Asynchronous, 115200 baud, 8N1, and tick NVIC USART2 global interrupt. TX of one side goes to RX of the other. Close the Serial Monitor before you flash.

Deep dive: RM0368 Rev 6, §19.3 USART functional description — p. 507.

The baud rate register BRR divides the clock

BRR sets the baud rate. The USART samples each bit 16 times, so it needs a clock of 16 × baud. It divides the 16 MHz clock PCLK1 by USARTDIV, the number in BRR.

\[\text{USARTDIV} = \frac{f_\text{PCLK1}}{16 \times \text{baud}} = \frac{16\,000\,000}{16 \times 115\,200} = 8.68\]

With a 4-bit fraction the baud rate is not exact. The receiver accepts 3.33 % total error; −0.08 % is safe.

Deep dive: RM0368 Rev 6, §19.3.4 Fractional baud rate generation — p. 519, Table 85 Receiver tolerance — p. 530.

I2C: two wires shared by many devices

I2C (inter-integrated circuit) uses two wires: SCL, the clock, and SDA, the data. The STM32 is the controller; each device is a target with its own address.

RM0368 Rev 6 says controller and target; HAL function names still say Master. Deep dive: RM0368 Rev 6, §18.3 I2C functional description — p. 475.

I2C START, STOP and data bits

The controller drives SCL. SDA may change only while SCL is low, with two exceptions: START and STOP.

Every target watches both lines. SDA changing while SCL is high means START or STOP, never data.

Deep dive: RM0368 Rev 6, §18.3.3 I2C controller mode — p. 479.

An I2C write: address, ACK, data

The controller writes the byte 0x08 to the LCD adapter at address 0x27.

After every byte the receiver pulls SDA low: ACK. If no device has the address, SDA stays high: NACK, and HAL returns HAL_ERROR.

Reading a register over I2C

A sensor keeps its values in numbered registers. A project example: read register 0xD0 of a BME280 at address 0x76. It holds the chip ID, always 0x60.

Repeated START (Sr): a new START with no STOP before it. The controller keeps the bus and turns from writing to reading.

Deep dive: RM0368 Rev 6, §18.3.3 I2C controller mode — p. 479.

An I2C LCD: the PCF8574 drives the display pins

The LCD adapter has only 4 data pins, so a character goes in two halves of 4 bits: two nibbles. The LCD takes a nibble when EN falls from 1 to 0.

One line of 16 characters: 16 × 450 µs = 7.2 ms, and the loop waits all that time. Write the LCD only when the text changes, at most every 200 ms.

SPI: four wires and a chip select

SPI (serial peripheral interface) has no addresses. The controller pulls one CS (chip select) line low to choose a device.

A shared bus: all devices connect to SCK, MOSI and MISO. Each device has its own CS.

Deep dive: RM0368 Rev 6, §20.3.1 SPI general description — p. 562, Clock phase and clock polarity — p. 564.

SPI modes: CPOL and CPHA

CPOL sets the SCK level when idle. CPHA picks the clock edge that reads the data. The device datasheet gives the mode.

SPI mode CPOL CPHA SCK when idle Data read on
0 0 0 low rising edge
1 0 1 low falling edge
2 1 0 high falling edge
3 1 1 high rising edge

Deep dive: RM0368 Rev 6, Clock phase and clock polarity — p. 564.

An SPI transfer with HAL

Read the BME280 chip ID over SPI: CS low, exchange 2 bytes, CS high.

Runs in main() CS is a GPIO output, labelled CS in CubeMX
uint8_t tx[2] = {0xD0, 0x00}, rx[2];                       // register 0xD0, dummy byte
HAL_GPIO_WritePin(CS_GPIO_Port, CS_Pin, GPIO_PIN_RESET);   // CS low: select the BME280
HAL_SPI_TransmitReceive(&hspi1, tx, rx, 2, 100);           // 2 bytes out, 2 bytes in
HAL_GPIO_WritePin(CS_GPIO_Port, CS_Pin, GPIO_PIN_SET);     // CS high: rx[1] = 0x60

To read, you must send: every clock moves one bit out and one bit in. First test: wire MOSI to MISO (loopback), then rx must equal tx.

For your project: the sensor datasheet names the interface. Many slow devices on two pins: I2C. One fast device with pins to spare: SPI. A PC or a radio module: UART.

Common serial communication mistakes

01 BAUD MISMATCH: the Serial Monitor at 9600, the board at 115200. The same wrong characters every time.

02 NO RE-ARM: HAL_UART_Receive_IT() not called again in the callback. One byte, then nothing.

03 NO SHIFT: 0x27 passed to HAL instead of 0x27 << 1. NACK and HAL_ERROR.

04 NO PULL-UPS: SCL and SDA never go high. Every I2C call fails.

05 WRONG SPI MODE: the device reads on the rising edge, the STM32 on the falling edge. Wrong bits, no error.

06 CS NOT DRIVEN: CS left high, so the device ignores the bus. Or CS high between the two bytes, so the device forgets the register.
