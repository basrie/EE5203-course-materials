EE5203 L10 Study Sheet

Serial communication: UART, I2C and SPI - Basri Erdogan

Essential question: In L09 the ADC value stayed inside the board. How does the board send it to your PC, show it on an LCD, and read a sensor, one bit after another on a few wires?

What you should be able to do

  • UART: calculate the time of a line and BRR; send with HAL_UART_Transmit(), receive by interrupt.
  • I2C: shift the address, read START, STOP, ACK and NACK, read a register, and time an LCD write.
  • SPI: drive CS, find the mode from CPOL and CPHA, and read a register with one full-duplex transfer.

UART: a frame of 10 bit times

A UART has no clock wire: the receiver uses its own clock at the agreed baud rate (bits per second). The line is high when idle. 8N1 frame = 1 start bit (low) + 8 data bits, D0 first + 1 stop bit (high), so one byte = 10 bits ÷ baud: 86.8 µs at 115200, 1.04 ms at 9600. The line 12300,1241,1000\r\n has 17 characters (count \r and \n) = 170 bits = 1.48 ms at 115200, 17.7 ms at 9600.

USART2 goes to the PC through the ST-LINK: PA2 = USART2_TX, PA3 = USART2_RX, AF7. CubeMX: Asynchronous, 115200, 8N1, tick USART2 global interrupt. PCLK1 = 16 MHz. BRR: USARTDIV = 16 000 000 ÷ (16 × baud) = 8.68 for 115200. Bits 15:4 hold the whole part (8), bits 3:0 the fraction in sixteenths (0.68 × 16 = 10.9 → 11 = 0xB): BRR = 0x08B, real rate 115 108 (−0.08 %). The receiver accepts 3.33 % total error, shared by both ends.

if ((g_ms - t_tx) >= 100U) {                    /* main(): one line every 100 ms */
    t_tx = g_ms;
    n = snprintf(buf, sizeof buf, "%lu,%lu,%lu\r\n", g_ms, raw, mv);
    HAL_UART_Transmit(&huart2, (uint8_t *)buf, n, 100);   /* 100 = time limit in ms */
}
HAL_UART_Receive_IT(&huart2, &rx_byte, 1);      /* once, before while (1) */
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart->Instance == USART2) {
        rx_ring[head] = (char)rx_byte;  head = (uint8_t)((head + 1) % 64);
        HAL_UART_Receive_IT(&huart2, &rx_byte, 1);   /* arm again for the next byte */
    }
}

HAL_UART_Transmit() writes each byte into DR when TXE = 1 and waits for TC = 1. It blocks for the time of the bits (1.48 ms), so never call it in an interrupt callback. A received byte sets RXNE; reading DR clears it. Overrun (ORE): a new byte is complete before DR was read, and the bytes after it are lost. The HAL gives the waiting byte to the receive callback with huart2.ErrorCode = 0x08; the arm there resets it, and receiving continues.

I2C: two wires, addresses and ACK

SCL (clock, from the controller) and SDA (data). On the Nucleo: I2C1, PB8 = SCL, PB9 = SDA, AF4, 100 kHz. The pins are open drain: pull-up resistors pull both lines high. START = SDA falls while SCL is high. STOP = SDA rises while SCL is high. Data changes only while SCL is low and is read while SCL is high, MSB first. After every byte the receiver pulls SDA low: ACK. SDA stays high: NACK.

The first byte is the 7-bit address and the R/W bit (0 = write). HAL wants the address shifted: 0x27 << 1 = 0x4E. Unshifted 0x27 addresses 0x13: NACK, HAL_ERROR. One byte with its ACK is 9 clocks: 90 µs at 100 kHz.

Transfer Bits on SDA (C = the controller sends, T = the target sends)
write 0x08 to 0x27 S · 0x4E (C) · ACK (T) · 0x08 (C) · ACK (T) · P
read register 0xD0 of 0x76 S · 0xEC (C) · ACK (T) · 0xD0 (C) · ACK (T) · Sr · 0xED (C) · ACK (T) · 0x60 (T) · NACK (C) · P

Sr is a repeated START: the direction changes from write to read without a STOP. The controller answers the last data byte with NACK: it wants no more data.

HAL_I2C_Master_Transmit(&hi2c1, 0x27 << 1, &data, 1, 100);           /* write one byte */
HAL_I2C_Mem_Read(&hi2c1, 0x76 << 1, 0xD0, I2C_MEMADD_SIZE_8BIT, &id, 1, 100); /* id = 0x60 */
for (uint8_t a = 1; a < 128; a++)                                     /* bus scan */
    if (HAL_I2C_IsDeviceReady(&hi2c1, (uint16_t)(a << 1), 2, 5) == HAL_OK) { /* print a */ }

Check every return value: HAL_OK, or HAL_ERROR after a NACK.

The I2C LCD. A PCF8574 backpack drives the 16x2 LCD (HD44780, 4-bit mode). PCF8574 bits: P0 = RS (1 = character, 0 = command), P1 = RW, P2 = EN, P3 = backlight, P4–P7 = D4–D7. One character = 4 bytes: high nibble with EN = 1, then EN = 0, low nibble with EN = 1, then EN = 0. Example: A (0x41), backlight on, gives 0x4D 0x49 0x1D 0x19. One transmit of 4 bytes = address + 4 bytes = 5 × 9 clocks = 450 µs at 100 kHz. A 16-character line takes about 7.2 ms. Write the LCD only when the text changes, at most every 200 ms.

SPI: chip select, full duplex, modes

SCK (clock), MOSI (controller to device) and MISO (device to controller) are shared. Each device has its own CS, a GPIO output: low before the transfer, high after it. No addresses, no ACK: a missing device reads 0x00 or 0xFF. Full duplex: each clock sends one bit and receives one, so to read you must send a byte. Speed: 1 to 20 MHz.

Mode CPOL CPHA SCK when idle Data read on
0 0 0 low rising edge
1 0 1 low falling edge
2 1 0 high falling edge
3 1 1 high rising edge 
uint8_t tx[2] = {0xD0, 0x00}, rx[2];    /* BME280: bit 7 = 1 means read; 0xD0 has it */
HAL_GPIO_WritePin(CS_GPIO_Port, CS_Pin, GPIO_PIN_RESET);   /* CS low  */
HAL_SPI_TransmitReceive(&hspi1, tx, rx, 2, 100);           /* rx[1] = 0x60 */
HAL_GPIO_WritePin(CS_GPIO_Port, CS_Pin, GPIO_PIN_SET);     /* CS high */

First test of a new SPI bus: connect MOSI to MISO (loopback); rx must equal tx.

Common mistakes

Mistake What you see
UART baud rate differs on the two ends the same wrong characters every time
No HAL_UART_Receive_IT() in the callback one byte, then nothing
I2C address not shifted (0x27 instead of 0x27 << 1) NACK and HAL_ERROR
No pull-ups on SCL and SDA the lines never go high; every I2C call fails
Wrong SPI mode no error, only wrong bits, often shifted by one place
CS not driven (left high, or released between bytes) 0x00 or 0xFF, or a broken transfer
