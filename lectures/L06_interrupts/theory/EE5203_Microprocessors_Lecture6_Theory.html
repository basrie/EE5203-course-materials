Polling misses a short button press

while (1) {
    if (HAL_GPIO_ReadPin(GPIOC, GPIO_PIN_13) == GPIO_PIN_RESET) {
        HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);
    }
    HAL_Delay(500);   /* other work: busy 500 ms, B1 is not read */
}

A polling program sees B1 only when it reads the pin, so a press between two reads is lost.

An interrupt pauses main() and runs a handler

An interrupt: hardware makes the processor pause main(), run one function, then continue where it stopped.

01 That function is the interrupt handler (ISR). Hardware starts it; main() never calls it.

02 The handler must be short: main() waits while it runs.

03 A timer (L07), the ADC (L09) and the UART (L10) interrupt the same way.

The interrupt path has six blocks, from B1 to your callback

Blocks 1 to 3 are ST peripherals; blocks 4 and 5 are the Arm core; block 6 is your code. The wire from block 2 to block 3 carries the interrupt request (IRQ).

B1 is active-low: a press makes a falling edge

Source: official MB1136 C04 schematic · UM1724 Rev 17, p. 24.

B1 PC13 Input reads
released high GPIO_PIN_SET
pressed (to ground) low GPIO_PIN_RESET

Press: high → low = falling edge.
Release: low → high = rising edge.

We want one event per press, so we select the falling edge.

EXTI detects the edge and sets the pending bit

An interrupt request is a peripheral’s signal to the processor: “I need service.” A pending bit stores it until the processor serves it, so no request is lost.

EXTI (External Interrupt controller) sets pending bit 13 on the falling edge of PC13; the request reaches the NVIC only if the mask bit EXTI->IMR bit 13 is 1.

Deep dive: RM0368 Rev 6, §10 EXTI — p. 205.

The NVIC chooses which request the CPU serves

Every peripheral’s request goes to the NVIC, the Nested Vectored Interrupt Controller. For each request it has one enable switch and one priority number.

01 Our request: B1 is request 40, EXTI15_10_IRQn. EXTI lines 10 to 15 share it.

02 Enable off: pending bit set, nothing runs: the most common lab bug.

03 Priority: 0 = most urgent; a more urgent request can interrupt a handler.

04 Our projects: all at 0, SysTick too: no handler ever interrupts another.

The vector table maps request 40 to a handler address

Filled by ST’s startup file before main() runs. You never write the table; you write only the handler.

The CPU saves its place and looks up the handler

When the NVIC passes request 40 on, the CPU does three steps in hardware:

01 Finish the current instruction; save the return address and registers on the stack.

02 Read row 16 + 40 of the vector table: the address of EXTI15_10_IRQHandler.

03 Jump to the handler. On return, restore the registers and continue main().

The IRQ handler calls a HAL helper, which calls your callback

Three files, three functions: CubeMX wrote the handler, ST wrote the helper, you write the callback.

stm32f4xx_it.cwritten by CubeMX 
void EXTI15_10_IRQHandler(void)
{
    HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_13);
}
stm32f4xx_hal_gpio.cHAL library 
void HAL_GPIO_EXTI_IRQHandler(uint16_t GPIO_Pin)
{
    __HAL_GPIO_EXTI_CLEAR_IT(GPIO_Pin);   /* PR bit 13 = 1 */
    HAL_GPIO_EXTI_Callback(GPIO_Pin);
}
main.cwritten by you 
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    /* your code */
}

First test: the interrupt version of the polling loop

Polling (slide 4): the loop reads PC13.

while (1) {
    if (HAL_GPIO_ReadPin(GPIOC, GPIO_PIN_13)
            == GPIO_PIN_RESET) {
        HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);
    }
    HAL_Delay(500);
}

Interrupt: the loop keeps the delay; the callback does the work.

while (1) {
    HAL_Delay(500);   /* other work: busy 500 ms */
}

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_13) {
        HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);
    }
}

The press arrives during HAL_Delay(): the callback runs, toggles LD2, and the loop continues. No press is lost. Live demo. This is only a test: application code does not belong in the callback.

A long callback freezes main()

Heartbeat in main():

while (1) {
    HAL_GPIO_TogglePin(GPIOA,
                       GPIO_PIN_5);
    HAL_Delay(100);
}

A callback that waits — wrong:

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    HAL_Delay(2000);
}

Live demo: press B1 and the heartbeat stops for good. HAL_Delay() counts SysTick interrupts. SysTick cannot interrupt our handler, so the delay never ends and the callback never returns.

Rule: a callback checks the source, records the event, and returns at once. No HAL_Delay(), no loops, no printing.

The volatile event variable

One variable carries the event from the callback to main().

volatile uint8_t button_event = 0;   /* 0 = no event, 1 = event waiting */
Without volatile With volatile
main() may reuse an old copy in a CPU register main() reads button_event from memory every time
the 1 from the callback can be missed the 1 from the callback is always seen

Deep dive: C11 draft N1570, §6.7.3 — p. 140 · M. Barr, How to Use C’s volatile Keyword.

The callback records the event; main() consumes it

The callback records the event: no LED action, no waiting.

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == GPIO_PIN_13) {
        button_event = 1;
    }
}

The main loop consumes the event and no longer polls PC13: reset the variable first, then act.

while (1) {
    if (button_event == 1) {
        button_event = 0;
        HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);
    }
}

The pending bit and button_event are two different flags

Both are called “flags”, but they live in different places and are cleared by different code. The exit ticket asks for this difference.

A real button bounces: one press, several falling edges

A mechanical contact does not switch cleanly once:

This is switch bounce. Each extra falling edge can set another interrupt request.

Software debounce accepts one edge per 80 ms

uint32_t last_press_ms = 0;

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    uint32_t now = HAL_GetTick();

    if (GPIO_Pin == GPIO_PIN_13 &&
        (now - last_press_ms) >= 80) {
        last_press_ms = now;
        button_event = 1;
    }
}

HAL_GetTick() returns the milliseconds since startup as a uint32_t.

The 80 ms guard: bounce settles within about 10 ms, so 80 ms skips every bounce edge. A fast double press takes longer than 80 ms, so it still counts as two presses.

The 10 ms figure comes from measured data: J. Ganssle, A Guide to Debouncing.

Checking the interrupt path in the debugger

Check the blocks in order and stop at the first one that fails. Read the registers in the SFR view in VS Code.

Block Check Evidence (SFR view)
1 B1 high released, low pressed IDR bit 13
2 EXTI falling edge, unmasked FTSR, IMR bit 13 = 1
3 NVIC request enabled handler breakpoint is reached
4–5 CPU handler entered PR bit 13 = 1 at the breakpoint
6 callback pin and flag watch GPIO_Pin, button_event
